# Wordbaazi — Shared Spec

**Brand: Wordbaazi** — an original daily word-guessing game with its own identity (name, palette, copy, word lists). Not affiliated with NYT/Wordle; no NYT assets, text, colors, or lists anywhere.

Three parts:
- `server/` — NestJS API (port 3000), SQLite storage
- `web/` — React + Vite + TypeScript (port 5173)
- `app/` — Flutter mobile app

## Game rules
- Guess a 5-letter word in 6 tries.
- Daily word: deterministic. `puzzleNumber = floorDays(nowLocal - 2026-08-25) + 1` (puzzle #1 on 2026-08-25); answer = `answers[(puzzleNumber - 1) % answers.length]` using `shared/answers.txt` (2000 words, pre-shuffled into puzzle order, lowercase). Both clients compute this locally from an embedded copy of the list.
- Word lists are CLEAN-ROOM: generated by `shared/generate-lists.js` from the public-domain ENABLE dictionary + Norvig frequency data. Never reintroduce NYT/original-Wordle lists.
- A guess must be in the valid-guess list (`shared/valid-guesses.txt`, 8636 words) OR the answers list.
- Tile evaluation (handle duplicate letters correctly — greens consume first, then yellows left-to-right): `correct` (green), `present` (yellow), `absent` (gray).
- One game per day per player. Game state persists locally (localStorage / shared_preferences) keyed by puzzle number so refresh/restart resumes mid-game.

## Design tokens (Wordbaazi — "Peacock & Marigold")
- Correct (peacock teal) `#0e7c86`, Present (marigold) `#e8a020`, Absent (dark charcoal) `#3d4451` — absent must stay much darker than correct so the states differ by lightness for colour-blind players.
- High contrast mode (persisted user setting, toggle in settings): correct `#e5691e` orange, present `#4f9ee8` blue, absent unchanged. Applies live to board, keyboard, stats highlight, and How To Play examples.
- Empty tile border `#cbd5e1`; tile with pending letter border `#94a3b8`
- Keyboard key default bg `#e2e8f0`, key text `#1e293b`; evaluated keys take tile colors with white text
- Text `#1e293b` (slate-800), page bg white `#ffffff`
- Tiles: ROUNDED (10px radius), soft shadow on filled tiles (`0 2px 6px rgba(15,23,42,0.18)`), 5px gap, bold uppercase letters ~2rem, sans-serif. Filled tiles have no border (solid color, white text).
- Board: 5 cols × 6 rows, centered, ~350px wide on web.
- Keyboard: 3 rows — `qwertyuiop` / `asdfghjkl` / `ENTER zxcvbnm ⌫`. Keys rounded 8px, bold, height ~58px. ENTER/backspace are 1.5× wide.
- Wordmark: bold sans, two-tone — "Word" in text color + "baazi" in peacock teal. NOT serif.
- Animations: tile "pop" on letter entry; staggered 3D flip reveal on submit; row shake on invalid word; dark rounded-pill toasts top-center.
- Header: hamburger (left); right side: stats bar-chart icon, help "?" icon, avatar / sign-in icon. Centered wordmark.
- How To Play modal: title "How To Play" (bold sans, large), subtitle "Guess the word of the day in 6 tries." — ALL copy in our own words (never NYT text). Examples use OUR words: TIGER (T teal/correct), MANGO (N marigold/present), CHAIR (H slate/absent); example tiles bordered + rounded, only the highlighted one filled. Sign-in link line, close ×.
- Win toasts by guess count 1→6: "Chha gaye!", "Zabardast!", "Kya baat hai!", "Shabash!", "Badhiya!", "Bach gaye!". Loss toast shows the answer.
- Stats view: "STATISTICS" — 4 numbers (Played, Win %, Current Streak, Max Streak) + "GUESS DISTRIBUTION" horizontal bars (slate bars, today's-win bar teal, right-aligned count labels).

## Auth
- Google Sign-In only. Client obtains a Google ID token (web: Google Identity Services; Flutter: google_sign_in), POSTs it to server, server verifies via `google-auth-library` against `GOOGLE_CLIENT_ID` env, upserts user, returns app JWT (`jsonwebtoken`/`@nestjs/jwt`, secret `JWT_SECRET` env, 30d expiry).
- Playing works WITHOUT sign-in (stats kept locally). When signed in, finished games are also posted to the server and the stats page shows server stats.

## API contract (server, prefix `/api`)
- `POST /api/auth/google` body `{ idToken: string }` → `{ token: string, user: { id, name, email, picture } }` (401 on bad token)
- `GET /api/me` (Bearer) → `{ id, name, email, picture }`
- `POST /api/games` (Bearer) body `{ puzzleNumber: number, won: boolean, guesses: number|null, board: string[] }` — `guesses` null when lost; `board` = the guessed words. Idempotent per (user, puzzleNumber): repeat posts ignored, returns saved record. → `{ ok: true }`
- `GET /api/stats` (Bearer) → `{ played, winPct, currentStreak, maxStreak, distribution: {1..6: number} }`. Streak = consecutive puzzleNumbers won (a missed day breaks it; computed against latest played puzzle).
- CORS enabled for any origin (dev-simple).
- SQLite file `server/data/hellowordle.sqlite` via better-sqlite3 (no TypeORM needed — keep it thin). Tables: `users(id TEXT pk = google sub, email, name, picture, created_at)`, `games(user_id, puzzle_number, won, guesses, board_json, created_at, PRIMARY KEY(user_id, puzzle_number))`.
- Env: `.env` with `GOOGLE_CLIENT_ID`, `JWT_SECRET`, `PORT=3000`. Provide `.env.example`.

## Client behavior
- On finish (win/lose): show toast with answer on loss; after ~1.5s auto-open stats view. Post result to server if signed in.
- Keyboard input: physical keys work on web too (a–z, Enter, Backspace).
- Local stats mirror server shape in localStorage/shared_preferences; merged view not required — server stats shown when signed in, local otherwise.
